本轮在隔离的新环境、空 HF 缓存和无旧构建产物的源码目录中完成数据链；**七个 records 文件的固定哈希全部一致**。公开同步状态见文末补记。

## 环境与输入

- macOS arm64，CPython **3.14.3**，CPU only。上游和本仓分开创建全新的虚拟环境，按各自 `uv.lock` 安装。
- 全空依赖包缓存的首次联网安装超时；成功安装复用了本机 **uv 依赖包缓存**。这不是“全空包缓存安装成功”，没有复用历史数据或 HF 缓存。
- 上游：transformers 5.17.0、datasets 4.8.5、jinja2 3.1.6、tokenizers 0.23.2；本仓：transformers 5.6.2、jinja2 3.1.6、tokenizers 0.22.2。
- 实际 builder 输入来自固定提交的干净 `git archive`，无已有 data。另已实际执行公开远程 `git clone`、固定 checkout 与 lock 哈希核对；克隆提交的 **59 个追踪文件**与 archive 输入逐文件字节一致。源码集合摘要为 `f822e9d804d0000627d3402decc881b3445ccb474d1faa9ae18051952cfa72c1`（按路径排序后的路径→文件 SHA256 JSON 的 SHA256）。没有在 clone 副本重复运行一遍 builder。
- 本仓使用本次候选源码的独立复制件。执行文档中的相同脚本、seed、比例与锁定 tokenizer；输出参数换为本轮专属隔离目录的绝对路径。没有覆盖历史 records 或封存 manifest。
- 两个 HF 缓存开始时均为空；五源及 Qwen/MiniCPM tokenizer 从公开源匿名下载成功，未使用 HF token、未下载模型权重。下载遇到超时后断点续传，最终获取步骤退出码 0。平台未来认证要求以其当时条件为准。

最终补强：清单解析在分配前限 64 KiB，并拒绝原始 JSON 的重复键；渲染错误统一只报类型、不含逐题 ID、答案或异常原文，重跑开始先撤销旧成功 manifest，失败输出不可用于后续步骤。渲染统计分组统一按 `(source, group_id)`，不拿 state 数冒充分组数。相应失效反例通过，补强后全量渲染也再次成功。

首次仓外路径实跑暴露第二次切分脚本仅在显示路径/记录 manifest 时要求仓内输入的问题；本轮仅把三处 `relative_to` 改为支持向上寻径，分层抽样、seed、行序和 JSONL 写法均未改。修复后仓外输入/输出实跑成功，固定 records 哈希通过。

**哈希契约只覆盖 records**。未发布历史 MiniCPM 渲染文件哈希，未比较跨 tokenizer 的渲染 bytes，也不比较含运行时间/路径的 manifest 整体 bytes。原有数据的开发消费/污染角色不因重建改变。
