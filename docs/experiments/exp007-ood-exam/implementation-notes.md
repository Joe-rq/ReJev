4. **`prep_exam.py` 的泄漏校验不查 `(source, group_id)` 口径**

   plan/005 第 3 步④要求「泄漏校验去掉 `(source, group_id)` 口径……只留 `statehash` + `id`」。

   另在 manifest 里**显式记 `"groups": null`**——不记会被读成 0，或被 `render.py` 那类
   `len({...})` 折叠成 1。

5. **`exam_report.py` 一律用 key 空间判正类，不用字母 label**

   初版实现把 gold 与 pred 都映射成字母 label（A/B）。**这是错的**：正类「phishing」落在哪个
   字母由**选项顺序**决定，按 label 判正类会在选项顺序不同的题目上静默判错。改为全程用
   key 空间（`phishing` / `legitimate`）。准确性判定不受影响（label↔key 题内双射）。

   `src/train/exam_report.py` 的判据 C 输出同步收窄（代码内注释留因）。

## 一处外部发现（登记，非本仓缺陷）

**上游 `analyze.py:24-27` 把 recall / FPR 的分母写死成常量 `/1000`。**

本卷 phishing 恰为 **1000/1000 平衡**，故其公布数字（1.3% / 42.7% / 0.0% / 16.8%）
**碰巧正确**——这是巧合，**不是设计正确**：换一张不均衡的卷子，同一份代码会给错数。

本仓 `exam_report.py` 一律按 gold 实际计数，并在自检输出里把「`n_pos==1000` 故两者同值」
如实登记为巧合。plan/005 第 7 步预警的「分母写死必须改」在**本卷上不构成实际错误**，
但该预警的方向是对的——它防的是把「代码写死」误当「数字会错」，实际是反过来的：
**代码写死了，但数字恰好没错**。

## 第三口径补做（2026-10-20 · #128 PR1）

**背景**：报告 §3.5 与本目录 README 早先声称客卷与本仓语料「三个口径零交集」。
前两个（`id`、`statehash`）由 `src/train/prep_exam.py:174-214` 的校验 3 执行；
第三个「跨 key 结构的字段值比对」**当时没有实现**——`plan/005` 第 102 行明写
「只留 `statehash` + `id`」。报告 v1.1.0 已先收窄为两口径，本轮补做后恢复三口径。

**实现**：`src/train/verify_exam_overlap.py`（只读）。
取每条记录 `state` 的**全部叶子值**，按 `src/data/render.py:statehash` 同一套归一化
（NFKC ＋ casefold ＋ `\w+` 词序列）后排序、以 `\x1f` 连接取 sha256（「内容袋」），
**集合（去重，更激进）与多重集（Counter 保留重数，更精确）两个口径都算**。
该哈希**对换 key 不变**（结构无关）；对字段值的改动，只要**归一化后仍不同**
就会变。大小写、标点、空白经归一化不可见，对这类改动**不敏感**。

**自检**（`--selftest`）：七类用例（换顶层 key / 嵌套换 key / 大小写 / 加一个字符 /
列表重排 / 重数双口径 / `messages` 回退），全部断言通过。

**结果**见下方「R9/R10 评审后的修订」里的**双口径主表**（2026-10-20，本机 `data/`，CPU）。
客卷 2,087 条 → 两个口径各 2,087 个内容袋；强口径 = 不同叶子值 ≥3 且归一化总长 ≥40
（排除短记录与常量字段的偶然碰撞）。**集合、多重集、强口径三者都是 0 命中。**

**边界**：比对对象是 `state` 字段，**不含 `question` / `options`**；因此报告把结论
限定为「至少不存在『同一内容、只换标识』式的同题换名」。若要覆盖题干与选项，
需另设口径（本轮未做）。

**复跑**：
```bash
uv run python -I src/train/verify_exam_overlap.py --selftest
uv run python -I src/train/verify_exam_overlap.py --json <out>.json
```
客卷与语料不随本仓发布（`REPRODUCING.md` §6.1）；缺输入时脚本以非零码退出并列出缺项，
**不静默跳过**。

### R9/R10 评审后的修订（2026-10-20）

1. **集合 → 集合＋多重集双口径**：第一版只用 `set`（忽略重数）。R9 有评审认为这是
   「假阴性」方向的洞；作者自核后**不成立**——集合口径把「只差重数」的内容**误判为同一**
   （多报），其命中集是多重集口径的**超集**；对「零重叠」这类否定性主张，集合口径的
   0 命中是更强的证据，不会漏掉真换名（换名保持重数不变）。为一次说清，现同时输出
   **两个口径**：集合（激进）与多重集（精确）。六个语料两个口径都是 **0 命中**。
2. **措辞收窄**：删掉「改一字即变」——归一化（NFKC＋casefold＋`\w+`）会把大小写、
   标点、空白抹平，这类改动**不可见**；准确表述是「归一化后仍不同的改动必变」。
   方向是**保守**（只会多报、不会漏报逐字改写）。
3. **发现并修正一处既有空转**：`prep_exam.py:198` 原写
   `{statehash(r["state"]) for r in d if "state" in r}`，而 `tev1-paper.jsonl`
   的 1,300 条**都没有顶层 `state`**（嵌在 `messages` 的 user JSON 里）——
   该语料的 `statehash` 口径**恒为空集**，先前报的「0 命中」是**空真**。
   用同一套回退重算：1,300/1,300 覆盖、与客卷 `statehash` 交集 **0**（结论不变）。
   `prep_exam.py` 已改为 `_state_of` 回退并断言全覆盖（取不到就炸，不静默跳过）。

`--selftest` 相应扩到七类用例：换顶层 key / 嵌套换 key / 大小写 / 加一个字符 /
列表元素重排 / 重数双口径（集合相同、多重集不同）/ `messages` 回退取 state。
脚本另加 `if not __debug__: raise`（禁 `python -O`，与 `prep_exam.py` 同一纪律），
退出码把集合命中、多重集命中、强口径与「有语料未检查」一并计入失败条件。
