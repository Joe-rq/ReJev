## Deviations（偏离原 plan 的决策）

1. **归档编号：`exp005-ood-exam` → `exp007-ood-exam`**

   plan/005 第 9 步写产物为 `docs/experiments/exp005-ood-exam/`。但 `exp005` 编号在 plan 落笔后已被
   `exp005-jev-comparison` 占用（真 Jev 对照，Issue #2），`exp006` 亦已被 `exp006-clean-weights` 占用。
   本项目实验编号**连续且不重排**，故改用 `exp007`。该撞号在 #9 收尾时已被顺带发现并登记。

2. **五臂而非四臂：补 `clean-r16`**

   plan/005 写四臂（`base` / `adapter` / `adapter_r64` / `tev1`），落笔于 2026-09-25——**当时 006 的
   干净权重轮尚未训练**。但 `clean-r16` 才是**已发布到 HF/魔搭的模型**（plan/007、plan/008）：
   OOD 读数缺了它，报告给出的就不是**已发布模型**的表现，而是两个内部实验臂的表现。
   故补第五臂，成本 +≈$0.17。

   `adapter`（exp002-r16）保留为**主判据臂**——plan/005 的判据 A–D 是围绕它预注册的，
   且它是 exp006 主对照的另一方（#24 的污染更正即针对这一对）。`clean_r16` 与 `adapter`
   的并排读数同时回答「剔源重训是否改变了分布外表现」。

3. **app 名 `rejev-eval-cross` → `rejev-eval-cross-v2`**

   规避 Modal 部署缓存：实测**同名的 app 在代码改动后仍可能跑旧版**（教训来自内部权重发布脚本（不随本发布集分发）的注释，Issue #23 踩过）。v1 承载四臂、v2 承载第五臂，
   两版 `MODELS` 仅差 `clean_r16` 一条目，已在 commit message 与 issue 评论中写明。

4. **`prep_exam.py` 的泄漏校验不查 `(source, group_id)` 口径**

   plan/005 第 3 步④要求「泄漏校验去掉 `(source, group_id)` 口径……只留 `statehash` + `id`」。
   原因：本卷**无分组键**（每题独立），该口径会退化成对 `source` 单键的比对，等于没查。
   另在 manifest 里**显式记 `"groups": null`**——不记会被读成 0，或被 `render.py` 那类
   `len({...})` 折叠成 1。

5. **`exam_report.py` 一律用 key 空间判正类，不用字母 label**

   初版实现把 gold 与 pred 都映射成字母 label（A/B）。**这是错的**：正类「phishing」落在哪个
   字母由**选项顺序**决定，按 label 判正类会在选项顺序不同的题目上静默判错。改为全程用
   key 空间（`phishing` / `legitimate`）。准确性判定不受影响（label↔key 题内双射）。

6. **判据 A / C 的预注册读法被收窄（2026-09-28，首轮双谱系评审 P1 触发）**

   plan/005 §判据 A / C 的预注册读法**含因果归因**：A 写「属**配方层面**的分布外缺陷」，
   C 写「结论升级为『**整套 tev1 配方**出了分布就塌』」。本轮证据不支持该归因：

   - 本卷**没有「未微调的 4B」对照臂**。若 4B 底座本身在这张卷上就差，塌陷便与配方无关。
   - 真 Jev 未塌（42.70%）只说明**存在不塌的解**——它与本仓配方在**模型与训练上都不同**，
     差异不止配方一项。

   故保留预注册判据的**查表结果**（README 的判据清单原文不改），另加「对判据 A / C 的
   必要补充（本仓追加，非预注册）」一段声明收窄后的实际声称：
   **两个已微调模型在本子集同向塌陷、且塌陷不是 2B 容量特有**；**不**声称「塌陷由配方造成」。
   `src/train/exam_report.py` 的判据 C 输出同步收窄（代码内注释留因）。

  > **补记（2026-09-28，第三轮评审 P2；2026-09-29 第六轮评审 B 线 P3-4 改写措辞）**：
  > 判据 A 的输出**当轮漏改**——本条偏离写的是「判据 A / C 被收窄」，而**那一轮**代码里
  > 只有 C 改了口径，A 当时**还写着**「配方层面的分布外缺陷」。**该缺陷已于同轮修复**：
  > 现在的 `judge()` 里判据 A 不再作因果归因（理由指向判据 C），本文件的「必要补充」段与
  > 之同步。这正是本仓的招牌形态：**改了 A 处、同源的 B 处还在**；偏离记录里那行
  > 「A / C」当轮是一句**假 ✅**。
  >
  > （改写的理由：原措辞「代码里却只有 C 改了口径，A 仍写着…」用的是**现在时**，而它描述的
  > 是**当轮**状态。第六轮评审 B 线据此判断「读者会以为代码现在还有这个 bug」——一条诚实
  > 记录因为时态含糊变成了误导记录。历史记录要保留，但**时态必须写死**。）

   > 这条偏离**不是**「结果与预期不符」——预注册的判据全部按字面成立了。收窄的是**从判据
   > 到结论的那一步**：观测到了同向塌陷，但「同向」不等于「同因」。

7. **plan/005 执行步骤 1（checkpoint 一致性核查）无法按原写法执行 → 取计划自带的保守分支**

   plan/005 第 1 步要求「比对上游 README 的 `hassan/Qwen3.5-4B-v1-new-69617472-bdc3c2fc`
   与本仓 `togethercomputer/Tev1-4B-experimental@0b7becf`，verify = config/权重指纹相符或
   不符；**不符则报告措辞改为「同门 4B」**」。

   **该核查无法执行**：上游那一臂不是本地权重——第三方客卷的 `run.py:7` 显示它经
   `api.together.ai` 的聊天端点调用，`report.json` 与 `README.md` 里只留了一个**端点名**
   （`hassan/Qwen3.5-4B-v1-new-69617472-bdc3c2fc`），**没有任何 config / 权重指纹可比**。
   本仓据此无从判定「相符」，而计划对「无法判定」没有分支。

   故取计划**自己给的保守措辞**：报告与本文档一律称其为**「同门 4B」**，不称同一 checkpoint。
   这不是新增的保守主义——它是第 1 步 verify 栏里原本就写好的那条回退路径，只是触发条件
   从「不符」扩到了「无法判定」。

   ⚠️ **对报告结论的影响（必须与读数一起读）**：报告 §2.5 第 3 条用「本仓实测逐位复现了
   上游公布值」来排除「本仓评测链路的 artifact」。在「同门」口径下，这条**仍然成立但强度
   要说明**：逐位一致的是**三个聚合值**（50.65% / 1.30% / 0.00%；本卷 1000/1000 平衡，
   故 recall 1.30% 与 FPR 0.00% 已唯一确定混淆矩阵 13/987/0/1000，不是四格独立吻合），
   它证明的是**本仓对该卷的判定口径与上游一致**，**不是**「两边跑的是同一个模型」。
   报告两版已就地加此限定（2026-09-28，第四轮评审 B 线 P1）。

## 一处外部发现（登记，非本仓缺陷）

**上游 `analyze.py:24-27` 把 recall / FPR 的分母写死成常量 `/1000`。**

本卷 phishing 恰为 **1000/1000 平衡**，故其公布数字（1.3% / 42.7% / 0.0% / 16.8%）
**碰巧正确**——这是巧合，**不是设计正确**：换一张不均衡的卷子，同一份代码会给错数。

本仓 `exam_report.py` 一律按 gold 实际计数，并在自检输出里把「`n_pos==1000` 故两者同值」
如实登记为巧合。plan/005 第 7 步预警的「分母写死必须改」在**本卷上不构成实际错误**，
但该预警的方向是对的——它防的是把「代码写死」误当「数字会错」，实际是反过来的：
**代码写死了，但数字恰好没错**。

## 已知限制（记录不修，报告已标注）

1. **本卷无分组键** → 无聚类 bootstrap，逐题 Wilson / McNemar 区间**偏乐观**
   （plan/005 风险 5）。exp002/003/005 的 1,892 题卷有 924 组，本卷连这个都没有。
2. **协议不可比**：上游 Qwen 用「原生字母 wrapper ＋ per-task regex」、Jev 用 native choice API、
   本仓用状态机约束 → 只做「同考卷、近似同协议」声称（plan/005 风险 1），
   沿用 exp003/004 的既有做法。
3. **预训练接触不可排除**：phishing 为 PhishNChips 合成邮件、公开可下载（plan/005 风险 2）。
4. **gold 来自数据集构造规则**，非独立人工标注。上游自述「简单 URL 启发式即 91.6%」——
   该数字是**数据集属性**，不是部署级安全保证（plan/005 风险 4）。这句须原样进报告。
5. **本卷一次性使用**：考卷与标签均公开。**本轮之后不得据其结果调参**；若将来调参，
   须声明该卷已不再是干净留出集（plan/005 风险 7）。
6. **`tool_risk` / `ticket_routing` 不作主口径**：60 条含主观/歧义类别、27 条有明显天花板
   效应且刻意清晰，**不合并成单一总分**（plan/005 风险 3）。
