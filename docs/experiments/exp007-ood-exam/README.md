# exp007 OOD 客卷评测

> **一句话**：把 ReJev-2B 与 Tev1-4B 放进一张**完全在训练分布之外**的第三方考卷——
> 答案是**剩不下**：两条 r16 臂（exp002 / exp006）的 phishing recall 塌到 **0**（恒判
> legitimate），准确率退化为恒常预测；r64 探针臂**朝反方向**退化（恒判 phishing，
> recall 96.20% / FPR 99.70%）——两个方向相反的塌陷。Tev1-4B 同样塌（recall 1.30%，
> **上游公布值**），而**未微调的底座反而是全场最好的本仓臂**。
>
> ⚠️ 本行 2026-09-29 第八轮评审 A 线 P0 更正：原文写「**所有** ReJev 臂的 recall 塌到
> 0」，与本文结果表 r64 行的「恒判 phishing（recall 96.20% / FPR 99.70%）」直接冲突
> ——r64 是**反方向**的塌陷，不是 recall 归零。

## 考卷

第三方随其评测代码公开的 2,087 题：`phishing` 2,000（二选一，随机基线 50%）、
`tool_risk` 60、`ticket_routing` 27。本仓只做**格式转换与校验**，不改题目、不改答案。

**为什么算「分布外」**：本仓全部训练与留出语料与该卷在三个口径上零交集——
① 题目标识（`id`）、② 内容哈希（NFKC ＋ casefold ＋ 词序列 sha256）、③ 宽松内容
（跨 key 结构的字段值比对，用于捕捉「同内容、不同 state 结构」的复用）。
口径 ②③ 都不命中，说明不是「同题换名」，而是真的新题。

转换脚本 `src/train/prep_exam.py` 做五重校验，全过：

| # | 校验 | 结果 |
|---|---|---|
| 0 | 上游清单 sha256 一致 | ✅ |
| 1 | gold（键）→ answer（标签）映射逐题自洽 | ✅ 2,087/2,087 |
| 2 | **用上游逐题 `correct` 字段在标签空间反证映射** | ✅ 2,087 题逐题一致 |
| 3 | 零泄漏（三口径 × 六个数据集） | ✅ 全 0 命中 |
| 4 | 两套 tokenizer 下的长度断言 | ✅ max 879 < 2048 |

校验 2 是**双向**证据：上游判 `correct == (prediction == gold)`（两侧都是键），本脚本改到
标签空间重算 `key2label[prediction] == answer`，逐题必须同值——**把映射方向写反会立刻炸**。

## 结果（phishing，2,000 题）

| 臂 | 准确率 | Wilson 95% | recall | FPR | 混淆（TP/FN/FP/TN） |
|---|---:|---|---:|---:|---|
| MiniCPM5-2B base | **57.05%** | [54.87, 59.20] | **14.20%** | 0.10% | 142/858/1/999 |
| ReJev-2B r16（exp002） | 50.00% | [47.81, 52.19] | **0.00%** | 0.00% | 0/1000/0/1000 |
| ReJev-2B 剔源 r16（exp006·已发布） | 50.00% | [47.81, 52.19] | **0.00%** | 0.00% | 0/1000/0/1000 |
| ReJev-2B r64 探针（exp004） | 48.25% | [46.07, 50.44] | 96.20% | 99.70% | 962/38/997/3 |
| Tev1-4B（官方权重） ¹ | 50.65% | [48.46, 52.84] | 1.30% | 0.00% | 13/987/0/1000 |

> ¹ **这一行的数字是上游公布值，不是本仓的测量结果**（Tev1-4B 许可「being finalized」未定，
> 本仓不发布对其的实测读数，见 NOTICE §4）。本仓跑过该权重的本地评测，读数与上游公布值
> 逐位相同；表中区间与混淆矩阵由这三个公布值在本卷 1000/1000 平衡的结构下唯一导出。
> 该行证明的是**评分口径一致**，既不证明「两边跑的是同一个模型」（见下条口径限定），
> 也不是对本仓评测链路的校验。

**50.00% 不是能力值**：它是「恒判 legitimate」在 1000/1000 平衡卷上的取值。r16 与
`clean_r16` 把**全部 1,000 条 phishing 都判成了 legitimate**，混淆矩阵一整列是 0。
读这张表时**准确率必须与 recall 一起读**——单看准确率会把「恒常预测」误读成「与上游同档」。

**Tev1-4B 一行逐位复现了上游公布值**（50.65% / 1.30% / 0.00%，混淆矩阵 13/987/0/1000）——
这是本仓第二次在第三方卷上做到逐位一致（首次是 exp003 在 tev1 官方开发集上）。
它说明的是：**把上游随卷附带的逐题产物喂进本仓分析器，评分汇总能复现上游公布值**。

> ⚠️ **口径限定（2026-09-28 第四轮评审 B 线 P1）**：上游那一臂跑在 **Together 托管端点**
> （`hassan/Qwen3.5-4B-v1-new-…`，见第三方客卷的 `run.py`），**没有 config / 权重指纹可比**，
> 故本仓称其为**「同门 4B」**而不称同一 checkpoint——这正是 `plan/005` 执行步骤 1 给
> 「比对不成立」预定的措辞。逐位一致的是**三个聚合值**，本卷 1000/1000 平衡，
> recall 1.30% 与 FPR 0.00% 已唯一确定那张混淆矩阵（故不是四格独立吻合）。
> 它证明的是**本仓对该卷的判定口径与上游一致**，不是「两边跑的是同一个模型」。

## 预注册判据的机械判读

四条判据在 `docs/plan/005_ood-exam-eval.md` 训前锁定。下面四行是**人工转录自分析器
`src/train/exam_report.py` 当前输出**（客卷数据不随本仓发布，这里没法现场生成）——
凡与本文冲突，**以分析器的输出为准**：

- **判据 A**：`recall 0.0000 < 10%` → 与官方 4B 复刻**同向塌陷**（本仓可复现该塌陷；
  **不作因果归因**——理由见判据 C）
- **判据 B**：`base recall 0.1420` **高于** r16 的 `0.0000` → 方向与「微调引入了塌陷」一致。
  **注意**：预注册写的是「明显高于」，而分析器既未定义阈值也未做显著性检验——
  本行**只报观测方向**，不构成「明显」的判定。（缺 `base` 或 `adapter` 任一臂时，
  分析器输出 `None`：配对判据缺一臂即**不可判读**，不得单臂下结论）
- **判据 C**：`r16 recall 0.0000` 与 `Tev1-4B recall 0.0130`（上游复刻）同向塌陷 →
  塌陷**非 2B 容量特有**。本判据**不含**「未微调的 4B」对照臂，故只排除「2B 太小」，
  **不构成「塌陷由配方造成」的归因**
- **判据 D**：`|0.5000 − 0.5065| = 0.65pp ≤ 10pp` → 字面判定「2B 与 4B 复刻在分布外同档」

> **对判据 A / C 的必要补充（本仓追加，非预注册）**：这两条判据的**预注册读法都含因果
> 归因**（A 写「属配方层面的分布外缺陷」、C 写「整套 tev1 配方出了分布就塌」），而本轮
> 证据**不支持**该归因——本卷**没有「未微调的 4B」对照臂**：若 4B 底座本身在这张卷上就
> 差，塌陷便与配方无关；真 Jev 未塌也只说明**存在不塌的解**，它与本仓配方在模型与训练上
> 都不同。故本仓只声称证据支持的部分：**两个已微调模型在本子集同向塌陷、且塌陷不是
> 2B 容量特有**；**不**声称「塌陷由配方造成」。
> 分析器 `src/train/exam_report.py` 的判据 C 输出已同步收窄；该收窄作为**偏离预注册读法**
> 记入 `implementation-notes.md` 的 Deviations。

> **对判据 D 的必要补充（本仓追加，非预注册）**：这里的「同档」是**两边都靠恒常预测**
> 拿到的同档，不是能力同档。判据 D 用准确率做标尺，而平衡二分类卷上「全判一类」自动
> 得 50%——该标尺在本卷上**恰好无法区分「有能力」与「没塌陷得那么彻底」**。
> 判据 D 的字面命中不应被引用为「2B 在分布外追平了 4B」。

## 配对检验（phishing 2,000 题，逐题 McNemar）

| 对照 | 左臂仅对 | 右臂仅对 | p（精确双侧） |
|---|---:|---:|---:|
| r16 vs base | 1 | 142 | 2.58e-41 |
| r16 vs clean_r16 | 0 | 0 | 1 |
| r16 vs tev1 | 0 | 13 | 0.000244 |
| r16 vs adapter_r64 | 997 | 962 | 0.442 |

三条读数：

1. **底座显著优于微调产物**：r16 只在 1 题上对而底座错，底座在 142 题上对而 r16 错。
   **出了分布，微调让模型变差了。** 但这是**相对**读数：底座 recall 14.20% 本身也**远低于**
   该卷 50% 的随机基线、FPR 仅 0.10%——底座在这张卷上同样是**近恒定预测**，只是退化得没
   那么彻底。应读作「底座退化得较轻」，**不是**「底座未退化」。
2. **剔源重训在 phishing 上零差异**：`r16` 与 `clean_r16` 在 2,000 题上**逐题完全相同**（p=1）。
   许可整改**在这个子集上**改变的不是分布外行为。（⚠️ 限定语是必要的：同页的分 suite 表里
   `tool_risk` 上 r16 = 85.00%、`clean_r16` = 86.67%，**并不相同**——「逐题完全相同」只成
   立于 phishing 这 2,000 题。）
3. **r16 与 r64 准确率无差异（p=0.442），但错误模式近乎互补**：r16 恒判 legitimate，
   r64 恒判 phishing（recall 96.20% / FPR 99.70%）。两个方向相反的塌陷。

> 区间口径：本卷**无分组键**（每题独立），故只有逐题 McNemar 可用，无聚类 bootstrap。
> 逐题独立性假设下区间偏乐观，这是本卷相对 1,892 题主场卷（924 组）的已知劣势。

## 效度边界

1. **本卷无分组键** → 无聚类 bootstrap；逐题区间偏乐观。
2. **协议不可比**：上游 Qwen 用「原生字母 wrapper ＋ per-task regex」、Jev 用其原生 choice
   API、本仓用状态机约束。故只做「同考卷、近似同协议」声称。
3. **预训练接触不可排除**：phishing 为公开可下载的合成邮件，无法排除任一模型在预训练阶段见过。
4. **gold 来自数据集构造规则**，非独立人工标注。上游自述「简单 URL 启发式即 91.6%」——
   该数字是**数据集属性**，不是部署级安全保证。
5. **本卷一次性使用**：考卷与标签均公开。本轮之后不得据其结果调参；若将来调参，须声明
   该卷已不再是干净留出集。
6. **「塌陷」的适用范围**：本读数只说明该配方在**这一张卷子的 phishing 二分类**上的行为。
   它**不能**外推为「ReJev-2B 在一切分布外任务上无效」——`tool_risk` 一列上 r16 为 85.00%，
   高于底座的 60.00%，即同一模型在同一张卷子的另一套任务上并未塌陷。

## 复现路径

```bash
# ① 考卷转换与校验（本地，零 GPU）——客卷不随本仓发布，先自备副本（见 REPRODUCING.md §6.1）
uv run python src/train/prep_exam.py --exam-dir <你的客卷目录>
#    产出 data/exam/exam.jsonl

# ② 评测（Modal，需账号与额度）——deploy + spawn，不要用 modal run 直接跑全量
modal volume put rejev data/exam/exam.jsonl /vol/data/exam.jsonl
modal deploy src/train/eval_cross.py
modal run tools/trigger_exam.py              # 秒级返回；五臂各自独立容器执行

# ③ 判读（本地，零 GPU；含上游自检，自检不过则拒绝产出）
uv run python src/train/exam_report.py --exam-dir <你的客卷目录> --dir <逐题结果目录>
```

判读脚本把上游随卷附带的逐题产物喂进自己，**必须逐位复现上游公布数字**
（50.65% / 62.95% / 1.30% / 42.70% / 0.00% / 16.80%），否则拒绝产出。
上游分析脚本把 recall/FPR 的分母写成常量 `/1000`；本卷恰为 1000/1000 平衡，故其公布数字
**碰巧正确**。本仓一律按 gold 实际计数，并在自检输出里把这一巧合如实登记。

## 结论

分布内 80.50% 与分布外「恒判 legitimate」之间，没有中间地带可辩护。
本卷给出的最硬一条是：**未微调的底座在分布外优于本仓的微调产物**（57.05% vs 50.00%，
p=2.58e-41），而同门 4B（上游托管端点，无权重指纹，故不称同一 checkpoint）同样塌陷
——所以这**不是「2B 太小」**的问题。
真 Jev 在同一卷上 recall 为 42.70%（上游公布值），并未塌陷：**塌陷不是任务的固有难度**
——存在不塌的解。但**归因止步于此**：真 Jev 与本仓配方在模型与训练上都不同，且本卷缺
「未微调的 4B」对照臂，故**不能**推出「塌陷是这套配方的产物」（见上「对判据 A / C 的
必要补充」）。
