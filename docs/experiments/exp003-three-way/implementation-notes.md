# exp003 实现记录

## Deviations（偏离原 plan 的决策）

1. **考卷取题路径变更（等价更强替代）**
   issue 原文：「从 `results.jsonl` 提取 1,300 条逐题 id，**在我们重建的数据中按 id 精确取题**」。实测该反查交集为 **0**（官方考卷取 v1 `test`/`policy_transfer` split，我们重建的是 `train`/`dev`）。改为直接用考卷本体 `resources/tev1/data/v1/records/{test,policy_transfer}.jsonl`，并与官方 results.jsonl 逐条对齐验证（1000/1000 + 300/300）。**意图（拿到逐题一致的考卷）不变，方案更强**：直接得到题面、gold 与选项顺序。按项目约定「偏离不停等、记入本文件」处理。

2. **约束候选集：全 A–X → 按题实际选项**
   首轮实现沿用了 exp002 的「首步允许全 A–X」。评审指出官方协议是 **regex per option list**（主考含 200 道二选一）。评估后确认：exp002 约束器从未触发（约束/无约束逐位相同），故此改动**不改变任何历史结果**；但为与官方可比，必须按题。已改为 `LETTERS[:len(options)]`。

3. **主动停止首轮评测并重跑**
   首轮评测跑到 base 完成、adapter 进行中时，独立评审线返回 3 个 P0（含上述约束集问题）。**主动停止**（确认远程容器已终止）→ 修复 → 重新生成考卷 → 重跑。已耗成本约 $0.2 计入本轮账单。

4. **base/adapter 在 holdout 上沿用 exp002 已验收结果，不重跑**
   两者协议逐位相同（同 `apply_chat_template` 参数、同 eos/pad、同约束逻辑），且新脚本在 tev1paper 上重跑 base 得到与旧代码**逐位一致**的结果（0 条预测不同），佐证口径未漂移。汇总脚本对此有显式 fallback 并在 `sources_used` 中标注来源文件。

5. **sanity 产物独立命名**
   `--n>0` 时输出 `cross-{model}-{paper}-dev{n}.jsonl`，杜绝「sanity 子集被全量运行当已完成跳过」这类混入。

6. **未接 wandb**
   与 exp002 不同，本轮评测未接 wandb（减少无人值守下的失败点）。逐题结果与 summary 全部落 Volume，主指标不依赖外部服务。

7. **成本闸：整次调用墙钟上限 3h**
   `MAX_RUN_SEC = 10800` 自函数入口起算，由独立看门狗线程兜底（覆盖模型加载、单次 generate、收尾汇总三段）；另设 15 分钟零写入自杀。Modal spend limit $0 与 credit 额度为最终外部闸。

**教训**：撤下一列数字时，**表格外的散文**会以「差值 / 比值」的形态把它漏出去。逐数字面

### 第 4 层实际拦得住哪些写法（**可核对清单**）

第六轮这里写的是「全角 / HTML 字符引用**任何一种写法**都拦下」。**那句话无法核对，而且
不成立**——第七轮评审 B 线据此判了阻断（P0），本条按实测逐项改写。以下每一种形态都有
对应的回归用例（`test_audit_public.py`，属发布工具链、不随本仓发布）；**不在这份清单里的
写法就是没拦**（下一节另列已知挡不住的）：

| 形态 | 由什么拦住 |
|---|---|
| 直写、带任意单位（`%`/`pp`/`个百分点`/`percent`）、或**什么单位都不写** | 值层——撤下的是**数**，不是「数＋单位」 |
| 数字与小数点写成全角 | NFKC 归一化 |
| HTML 字符引用（十进制 / 十六进制 / 带前导零） | 实体解码 |
| **免分号**的数字字符引用（`&#57&#52&#46…`，浏览器同样接受） | `html.unescape`（自带分号可选） |
| 零宽与不可见字符插在数字中间（ZWSP、ZWJ、BOM、SOFT HYPHEN…） | 剥离层（**NFKC 对它们无一有效**） |
| 用空白字符实体把数字拆成两段（空格 / NBSP / 制表 / 换行） | 榨空白变体（**并集**，不替换） |
| 逗号或中文句号被当作小数点 | 逗号变体（**只用于值层**） |
| **上两条同时用**（逗号当小数点 ＋ 空白拆段） | 变体的**笛卡尔组合**（第八轮实测补上，此前该组合整类放行） |
| HTML 注释夹在数字中间（渲染后注释消失、两截拼回原值） | 渲染近似变体（去注释后**再**匹配，与原文并列） |
| 数字中间插 Python 数字字面量的下划线分隔 | 去下划线变体（**不**改动标识符） |
| 科学计数法（整数尾数、点号开头、负指数） | **求值**比对（不是按形态匹配——按形态会误伤统计 p 值）。**例外**：一位小数撤下值的「整数尾数别名」刻意不拦，见下文「四层都挡不住什么」 |
| 中文数词（小写 / **大写**（壹贰叁…）/ **中阿混写** / **并置逐位念**（`九四`＝94）） | 中文数词规则，同样**求值**而非按形态 |
| **Markdown 反斜杠转义**的小数点（渲染后反斜杠消失、两截拼回原值） | 反转义变体（第九轮 A 线 P0-2①，只还原标点前的反斜杠） |
| **空行内 HTML 标签**拆数字（空标签渲染后不输出；含 1–6 层嵌套对、`<br>` 等空元素（属性含 `>` 亦算）） | 剥空标签变体（同上②，至多 6 趟） |
| **实体编码的下划线**（`&#95;` 解码后才是分隔符） | 去下划线根改在**解码后**文本上找（同上③） |
| 注释夹在**科学计数法内部**（指数前的连接处被注释隔开） | 科学计数法闸改吃全部变体（第九轮 B 线 P0-1——第八轮的注释变体漏接了这条闸） |
| **非 ASCII 十进制数字**（阿拉伯-印度 ٠١٢٣…、天城 ०१२३… 等 Unicode Nd 族；NFKC 不折它们） | 第一级归一新增 Nd→ASCII（第十三轮 A 线 P2） |
| **行内强调/行内代码/删除线定界符**（含三星与**两侧各 ≥2 的超长 run**、**非词内**下划线强调（开闭**等长**才成对）；定界符夹在数字中间，渲染时被吃掉）、**插在数字中间的带内容标签**（下标/上标类，属性含 `>` 亦算；数字仍可见）、**只开不闭或只闭不开的标签与交叉配对**（渲染时整族丢弃、数字随之粘合）、**行内链接壳**（destination 含平衡括号、`url "title"`、尖括号式、**引用式** `[4][r]` 亦算；链接文本保留、数字可读）、**成对 `$` 的数学定界符**（含 display `$$` 两端空白与**跨行**写法——渲染时两端空白一并被吃掉、span 与两侧文字紧贴） | 行内定界符族（第十三轮 B 线 P1-1 起，第十四轮 A/B 两线补全六类形态；第十六/十七轮续补：title 状态、跨代码 span 外壳、超长 run、math、未闭合标签；第十八轮续补：`$$` 空白与跨行、闭标签族栈式配对、围栏与 raw HTML block 上下文、星号 run 剩余量模型、链接后缀文法与阶段拆分） |

  **第 4 层是这一条的唯一例外**：它只认数值，故**列在清单里的**那些数换成上表任何形态都
  拦得住。
- **第 2 层只认 `Tev1-4B` 这一个字面量**：`官方 4B`、`Tev1`、大小写变体都匹配不到。
  这不是理论缺口——`plan/005` 的那句 P0 写的正是**官方 4B**，它靠第 1 条而非第 2 条兜住。
- **舍入 / 近似形态不拦，且**判据层根本冲突**。理由不是实现难，而是**判据自相矛盾**：
  撤下值里有两个本身就是一位小数，而**允许发布的官方公布值中恰有一个是另一个撤下值的
  一位舍入**——拦「一位舍入」会连带拦掉那个允许值。**不是所有「看起来像泄漏」的形态都能
  机械拦截：当拦截判据与允许清单发生交集时，问题从实现层升到判据层，此时正确的动作是
  如实声明边界，而不是硬做一条会逼出豁免的规则。**残余风险：把撤下值少写一两位不会被拦
  ——它损失精度，但读者仍能读出大致量级。
- **一位小数撤下值的「整数尾数指数别名」不拦**（第八轮声明、第九轮 A 线 P2-2 更正论据）：
  把一位小数写成「整数尾数 + 指数」后，它与正文里**独立成词的合法短科学计数法**
  （`1e3`、`5e2` 这类普通记法）形态完全重合。⚠️ 本条早期版本的论据是「`uv.lock` 的
  sha256 片段会切出该形态的 token」——那个形态（token 两侧紧贴字母数字）是**边界断言**
  挡的，不是本条的功劳；第九轮实测**撤掉本条边界，导出集新增命中 0 处**，即它不是被
  现存误报倒逼的，而是防未来误报的**预防性声明**。与上一条同源：
  **拦截判据与允许内容发生交集时，问题从实现层升到判据层**，此时如实声明边界比硬做一条
  会逼出豁免的规则更诚实。该边界由一条专门的回归用例钉住——它现在**故意**不变红。
  ⚠️ 本条初稿曾把**真实的撤下值连同它的指数别名**直接写出来当例子，导出闸当场拦下——
  这正是本节末尾「闸的说明文字是闸自己的盲区」的第三次复发，改后不再写出任何具体数值。
  第九轮重写「可核对清单」时**第四次复发**：新补的五种形态行又把真实撤下值当示例写进
  去，闸再次当场拦下（新增的反转义/剥标签/千分位变体让这些示例形态全部现形）——
  该纪律没有例外，示例一律用与全仓任何读数无关的合成数或不写出具体形态。
- **同值的补零/前导零写法不拦（第十三轮 B 线 P3-5 登记）**：在撤下值末尾补零或
  加前导零的形态，值层正则的前后边界（防子串误报的那对断言）
  构造性地放行它们。补零不是自然书写，人不会无意写出；登记为边界而非实现拦截。⚠️ 本条初稿曾把
  真实撤下值的补零形态直接写进示例——值层按本边界放行它们、闸不拦，但读者一眼
  能读出撤下值（「说明文字是闸的盲区」的又一形态：**边界声明不得引用真实值的任何
  可读变体**），改写后不再含任何字面值。
- **行内定界符族的边界（第十四轮 A/B 两线登记，第十五轮 B 线 P1-1/P1-2/P2-1 改写，
  第十七轮 A 线 P1-1/P1-2、B 线 P1-1/P1-2/P1-3 与本轮自审扩写）**：
  ① 剥除**至多 6 趟**（与空标签根同量级）；② **代码 span 内按字面保留、span 外照常解析**——
  按配对反引号把行切成 span 与非 span 片段：span 片段只取渲染文本（去定界符，外加规范的
  「内容首尾皆空格且不全为空格则各去一格」），其中的强调/删除线/链接写法一律按字面保留
  （CommonMark §6.1：code span 内容除实体解码外不再解析）；非 span 片段跑全套根。⚠️ 切分本身也服从 CommonMark：反斜杠转义的反引号、行内标签
  里的反引号都不是定界符；**找不到等长闭合 run 的整段反引号 run 并入普通文本**
  （第十七轮 A 线 P1-2 实测：逐格前进会把未配对的整段 run 与后面的单反引号错配成代码
  span，令其中的强调不再解析）。**外壳跨在代码 span 两侧**时（链接/删除线/标签的开闭
  定界符分别落在 span 左右），取 span 文本与剥壳按**占位符**先掩码、后拼回
  （第十七轮 B 线 P1-2），两者互不吞并。
  先前的两种做法各错一半——「先剥代码定界符、再剥其中的链接壳」把代码里的语法当成真
  语法（误报，A 线第十四轮），而「含反引号的行只剥代码定界符、其余全套让位」又把 span
  **外**的真形态漏掉（第十五轮 B 线实测：代码 span 与标签/链接/下划线共存于一行时，
  渲染后是连续读数而四层全放行）；**「代码与链接共存时链接根让位」那条边界登记随本轮
  改法一并作废**；③ 三星/删除线的**纯标点内容**按字面保留（CommonMark 侧翼规则：
  `51***%***` 不开强调——定界符后跟标点且前是数字时渲染保持字面，剥它就是误报；近似
  判据为内容须含字词字符）；④ 链接 destination 按文法**平衡扫描**（尖括号式可含空格、
  `url "title"`、任意深度平衡括号；第十五轮 B 线 P1-1 实测，先前的一层括号正则让前三类
  整族放行）；⚠️ 扫描要区分 destination 与 **title** 状态——title 引号内的括号与尖括号
  不是链接语法（第十七轮 A 线 P1-1：先前在 title 的右括号处提前收尾、留下可见的连续
  读数）；⚠️ 第十八轮把链接根改为**逐段后缀文法**（`(` → 可选空白 → destination → 可选
  空白 → 可选 title → 可选空白 → `)`，任一段不合法即整条不是链接、一律**不剥**）：旧写法
  只看括号配没配上，于是「title 之后还有残余」「destination 后跟裸词」「挂了两个 title」
  这些 pandoc 并不认作链接的形态被整族误剥（假阳）；同轮实测确认**括号式 title 不容
  嵌套**（`(x (a(b)c))` 渲染后原文照旧），故 title 只扫到第一个未转义 `)`。又因链接文法
  吃的是**原始文本**、而标签根会抹掉行内标签，两者同趟跑会让抹完标签的文本在下一趟被
  错认成合法链接（`x <b>`、`<a b>c` 整族假阳——注意是**带空格**的 `x <b>`：抹掉标签后
  `(x )` 成了合法链接；不带空格的 `x<b>` 本就是合法 destination，抹与不抹都是链接，不是本族），故链接根拆成**阶段 0**（对原文剥到不动
  点，其间不碰标签）、其余各根进**阶段 1**，相位隔离；⑤ 下划线的 run **开闭等长**、长度不设上限（未配对的 `_` 保留、读者仍看得见），
  但**前为字母数字时不算强调**（GFM 对 `_`
  的开启条件：`manylinux_2_2014` 这类词内下划线与紧贴前导数字的写法渲染后原样，剥它们
  才是误报——第十五轮 B 线 P1-2 的正确判据，其原举例中「前是数字的 `__`」一例经 pandoc
  实测并不开强调，按真值只收前为空白/标点的 run）；⑥ 星号 run 按 CommonMark 的**逐渐
  消耗**模型求剩余量（第十七轮 B 线 P1-3 提出超长 run 一例；第十八轮 A 线 P2-2 实测归纳成
  模型）：一对 run 夹一段内容时，若左 run 前是字词字符，整对受 rule 9 管辖且按**原始 run
  长度**判（`(l+r)%3==0` 且两者不都是 3 的倍数 → 一个也不配）；其后两侧各 ≥2 就各吃 2、
  否则各吃 1，吃到一侧见底，**消耗的是靠内容一侧的星、余星总紧贴内容**（`9****4.03***`
  渲染后是 `9*4.03`；`9*****4.03***` 渲染后是 `9**4.03`——余星数随两侧 run 长度变化，
  按剩余量剥）。先前三支根各管一段、接缝处漏配（族 X 18 格放行）——
  并为**一支根**后按值层同判据对拍 pandoc 真值 0 不符；

  ⑦ 成对 `$` 的**数学定界符**按 pandoc 的 tex_math_dollars 语义剥除——开 `$` 右侧非空白
  且非 `$`、闭 `$` 左侧非空白、反斜杠转义的 `$` 不算定界符（第十七轮自审、pandoc 逐形态
  实测归纳），且 **display `$$` 同属该族**——两端空白连同跨行的换行一并被渲染器吃掉，
  span 与两侧文字紧贴（第十八轮自审 pandoc 实测：`9$$\n4.03\n$$` 折叠后是连续的 `9` 与
  `4.03`）；⑧ **只开不闭或只闭不开的行内 HTML 标签**按「不渲染」剥除——渲染时标签丢弃、
  数字随之粘合（第十七轮 B 线 P1-1；第十八轮补**闭标签族与交叉配对**，`</b>` 单独出现、
  `<b>x</i>` 同样整族丢弃）；⑨ **围栏代码块与 raw HTML block 内的行一律不跑行内族根**
  （第十八轮自审，pandoc 逐形态实测）：CommonMark 在这两类上下文里不解析行内 Markdown（§4.5/§4.6），
  读者看到的分别是原文（围栏）与去掉标签后的原文（raw block）——行内根照跑会把围栏里的
  `$(…)`、`__version__` 改写掉（偏严方向的误报），故按行级上下文分流，只取各自的字面
  可见文本。
- **空标签剥除有 6 趟上限（第十一轮 A 线 P1 / B 线 P2-2 登记）**：每层嵌套剥一趟，第
  7 层起的嵌套空标签不再剥、值层放行。设上限是防恶意深嵌套让扫描器停不下来；7 层以上
  的单行嵌套已远离正常文档形态，列为人工复核范围。⚠️ 发布物这一侧此前写「剥到不动点」
  而**实现是 3 趟上限**——说明文字强于实现、且上限未登记，两条都是本文件自订准则
  （「不在清单里就是没拦」「如实声明边界」）所禁止的；本轮改为 6 趟并在两处同步写明数值。
- **等值算式不拦**：把撤下值写成表达式、分数或别的进制（读者一算就得到原值）需要算术
  解析，A、B 两条线均认可**列为人工复核范围**，不做机械判据。
- **物理跨行拆分不拦**：把一个小数拆在**两行**上需给扫描器引入跨行上下文，改动面覆盖它的
  签名与全部调用点，而渲染后中间隔了换行、可读性本就受损。**注意与上表的空白实体区分**：
  后者**单行即可写成**、渲染后读者看到的只是「数字 空格 小数部分」——两者症状相似，
  可修性完全不同，实体注入那一条已修掉。⚠️ 第十八轮补：**display `$$` 的跨行不在本条
  之列**——它的两端换行由渲染器吃掉、span 与两侧文字紧贴（pandoc 实测），故已按行内族
  折叠处理；本条只指普通文本里的小数被物理拆到两行。
- **非 Markdown 文件（`.sh`/`.py`/`.toml` 等）同样跑行内族根，方向是偏严**（第十八轮
  登记）：这些文件不经 Markdown 渲染，行内族根在它们身上是**多剥**——`src/align/check.sh`
  里的 `$(cd …)` 会被数学根吃成 `(cd …`，`_MD_UNDERSCORE` 也会动 dunder 之外的形态。
  按本仓准则本应「不在清单里就是没拦」，这里是清单之外**多**拦的一种；它不制造漏检
  （只会多报），故登记为边界而非实现拦截。⚠️ 同一轮 B 线把散文里的 dunder
  （`transformers.__version__`）也列进本条——那半条**不采纳**：pandoc 实测散文里它渲染
  为 `<strong>version</strong>`，读者看到的就是 `version`，剥它**正是**真值所要求的
  （该处改法经实测反证不成立）。

⚠️ **闸的说明文字是闸自己的盲区**（第六轮评审 A、B 两条线**各自独立**抓到，第七轮修复
批次里又重犯了一次，故写在这里）：这一节初稿曾拿**真实的撤下值**当例句来「演示」裸数字
躲得过检查——那句「演示」本身就成了泄漏，而当时的三层全放行。第二次是本节按第七轮结论
重写时，又在「拦得住什么」的表里把真实读数逐个写成示例，导出直接中止。两次都是同一个
形态：**说「这里躲得过检查」的那句话，本身就是一次绕过**。故本节一律用与全仓任何读数都
无关的合成数（如上面那个「考了 123 分」），且**不写出任何真实读数**——示例数字不得选
真实读数，这条纪律没有例外。

所以：**四层守的是「已见过的形态 ＋ 已登记的文件 ＋ 已登记的值」，不构成「不会泄漏」的
证明**——用**上面那份清单之外**的措辞叙述一个**尚未进清单**的读数，仍可能绕过；两道声明表
里也有 **21 个文件只有一行字**（同上，重导时的快照）。真正的第一道防线仍然是**人**：被撤下的
只有一个第三方模型的实测列，凡涉及它的句子都要逐句过目；这四层只是把它变成「漏了会说一声」，
而这一声在 21 个文件上很轻。

⚠️ 2026-09-29 第八轮评审 B 线 P2 更正：原文写「…并**稳定为 0**」，未限定是哪一场评审。
本仓**发布准备期**另有一场双谱系评审（见上文各轮小节，至第八轮仍在进行，且第 6、7 轮
各自报出过新的 P0）——「稳定为 0」只对本实验那 5 轮成立，对发布期那场不成立。两场评审
